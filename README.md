# RESTRUCT — Discord-бот семьи

Бот на [disnake](https://docs.disnake.dev/) для управления автопарком, тикет-системой,
предупреждениями, AFK-статусами, голосовыми каналами и коллами на ВЗП.

## 1. Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Настройка

1. Скопируйте `.env.example` в `.env` и вставьте токен бота (Discord Developer Portal → Bot → Token).
   При желании укажите `GUILD_ID` — тогда слэш-команды синхронизируются мгновенно на этом сервере
   вместо ожидания до часа при глобальной синхронизации.
2. Скопируйте `config.example.json` в `config.json` и заполните ID вашего сервера:
   - `channels.logs` — канал для логов (варны, закрытые тикеты).
   - `channels.join_to_create` — голосовой канал «Создать канал», при входе в который создаётся
     личная комната.
   - `channels.voice_category` — категория, в которой будут появляться личные голосовые каналы
     (можно оставить `0`, тогда каналы создаются в той же категории, что и «Создать канал»).
   - `channels.news` — канал для команды `/news`.
   - `channels.recruit_apply` — канал с тикет-панелью заявки в семью; на него ссылается
     приветствие новых участников (в канале и в ЛС).
   - `tickets.<curator|recruit|general>.category_id` и `.role_id` — категория для
     создаваемых тикет-каналов и роль персонала, которая должна их видеть и получать пинг.
   - `tickets.recruit.in_progress_role_id` — роль, которая выдаётся заявителю, пока сотрудник
     ведёт его заявку (с момента «Забрать» до «Принять»/«Отклонить»), и снимается сразу после
     решения.
   - `tickets.recruit.accept_role_id` — роль, которая выдаётся заявителю при одобрении заявки.
   - `vzp.positions` — словарь «Название должности → ID роли» для команды `/vzp`.
   - `warns.threshold` — при скольких активных предупреждениях бот пингует руководство в логах
     и автоматически банит участника (см. раздел «Предупреждения» ниже).
   - `warns.escalation_role_ids` — список ID ролей, которые пингуются при достижении порога.
   - `warns.auto_ban_days` — на сколько дней автоматически банит участника при достижении
     `warns.threshold` активных предупреждений (по умолчанию 3).
   - `warns.auto_expire_days` — через сколько дней после выдачи предупреждение снимается само
     (по умолчанию 7, то есть неделя).
   - `autorole.role_ids` — список ID ролей, которые бот автоматически выдаёт каждому новому
     участнику при входе на сервер (можно указать несколько).
   - `moderation.leader_role_ids` — роли с прямым доступом к `/ban /unban /permban /unpermban
     /kick`, они же решают по заявкам на наказание.
   - `moderation.mute_role_id` — роль, начиная с которой (и выше по иерархии сервера) доступны
     `/mute /unmute`.
   - `moderation.requester_role_id` — единственная роль, которой доступна `/punishment request`.
   - `moderation.request_channel_id` — канал, куда падают заявки на бан/разбан/кик на одобрение.
   - `moderation.log_channel_id` — канал логов всех наказаний (прямые команды + заявки).
   - `roles.log_channel_id` — канал логов выдачи/снятия ролей через `/role`.
   - `restruct_announce.role_id` — роль, которую тегает `/restruct_announce send` и которой
     рассылает объявление в личные сообщения.
   - `restruct_announce.channel_ids` — каналы, куда одновременно публикуется объявление.
   - `brand_color` — акцентный цвет embed-сообщений (HEX, например `"0x8B0000"`).
   - `footer_icon_url` — иконка в футере embed-сообщений (необязательно).

## 3. Права бота в Discord Developer Portal

Во вкладке **Bot** включите привилегированные intents:
- `SERVER MEMBERS INTENT`
- `MESSAGE CONTENT INTENT` — нужен для канала-трубы вебхука ЮKassa (`cogs.shop`)
- `PRESENCE INTENT` — нужен для подсчёта участников онлайн в `/stats` (`cogs.stats`)

При приглашении бота на сервер выдайте права:
`Управление каналами`, `Управление ролями` (ниже роли бота), `Отправка сообщений`,
`Управление сообщениями`, `Встраивание ссылок`, `Прикрепление файлов`,
`Просмотр канала`, `Подключение/Перемещение участников` (для голосовых каналов),
`Модерация участников` (для варнов и `/mute`), `Блокировка участников` (для `/ban`/`/permban`),
`Кик участников` (для `/kick`). Дополнительно `Управление сервером` — без него `/stats` просто
пропустит поле «Активных инвайтов», всё остальное работает и без него.

Роль бота должна находиться выше ролей персонала, которым он управляет, и выше ролей,
которым он должен запрещать видеть тикет-каналы.

## 4. Запуск

```bash
python bot.py
```

## 5. Первичная настройка панелей

Все команды, создающие постоянные панели (`/curator`, `/recruit`,
`/ticket`, `/voice`, `/vzp`, `/news`, `/cars adm` через кнопки, `/img`), доступны только участникам
с правом **«Управление сервером»**. `/cars show` и `/afk` доступны всем.

1. Настройте картинки панелей командой `/img` (панель → изображение). Бот скачивает файл и
   переприкрепляет его заново при каждом вызове панели — ссылка Discord CDN никогда не протухнет.
2. Вызовите нужные команды панелей в соответствующих каналах — панели используют
   картинку, заданную на шаге 1. При повторном изменении картинки командой `/img`
   панель нужно вызвать заново, чтобы обновление вступило в силу.

## Тикеты: что умеет бот

- **Клейм только один раз** — забрать тикет может любой сотрудник с нужной ролью, но повторно
  забрать уже занятый тикет нельзя (кроме как участнику с правом «Управление сервером» —
  для форс-переназначения). Повторное нажатие «Забрать тикет» тем же сотрудником освобождает тикет.
- **«От администрации»** — кнопка доступна только сотрудникам, ведущим тикет. Открывает окно
  ввода текста и публикует сообщение в тикете от имени «Администрации» без указания автора —
  реальный отправитель фиксируется только в канале логов, игрок его не видит.
- **Рейтинг после закрытия** — после закрытия тикета автору в личные сообщения приходит запрос
  оценить работу персонала (1–5 звёзд), результат уходит в канал логов вместе с тем, кто вёл тикет.

## Наказания

Два независимых уровня доступа, настраиваются через `moderation.*` в `config.json`:

- **`/ban /unban /permban /unpermban /kick`** — только `moderation.leader_role_ids`
  (по умолчанию own + dep.own). `/ban` требует срок (`1d`, `12h`, `3d12h` — число + d/h/m,
  можно сочетать, максимум 365 дней), остальные — только причину.
- **`/mute /unmute`** — доступны `moderation.mute_role_id` **и любой роли выше неё** по
  иерархии сервера (не только этой одной роли) — реализовано через `member.timeout()`, поэтому
  снятие мута по истечении срока делает сам Discord, боту для этого ничего проверять не нужно.
  Максимум для `/mute` — 28 дней (ограничение Discord).
- Временный `/ban` бот отслеживает сам (`data/moderation.json`) и автоматически разбанивает
  по истечении срока (проверка каждые 5 минут) — у Discord нет встроенных временных банов.

**Заявки на наказание** — `/punishment show` публикует постоянную панель с меню выбора типа
(вызывает руководство один раз в нужном канале, как `/rules show`/`/cars show`); `/punishment
request` — то же самое, но разовым эфемерным окном лично себе, без панели. Доступно только
`moderation.requester_role_id` (по умолчанию та же роль, что и порог для мута) — проверка прав
встроена прямо в меню на панели, а не только в команде, так что нажать его без нужной роли не
получится, даже если панель видят все. Меню предлагает бан/разбан/пермбан/снятие пермбана/кик/
предупреждение/снятие предупреждения (всё, кроме мута, на который у этой роли и так есть прямой
доступ), затем открывается анкета: игрок, срок (только для временного бана), причина,
доказательства. Готовая заявка публикуется в `moderation.request_channel_id` с кнопками
**Одобрить**/**Отклонить** — решать может только `moderation.leader_role_ids`. Одобрение сразу
выполняет наказание; отклонение требует указать причину, пишет её в `moderation.log_channel_id`
и отправляет автору заявки личное сообщение. Все наказания — и прямые команды, и одобренные
заявки — логируются в `moderation.log_channel_id`.

Заявку на предупреждение/снятие предупреждения одобряют так же, как остальные — снятие снимает
самое старое активное предупреждение цели (для точечного выбора конкретного номера у руководства
есть `/unwarn`).

**Быстрый тег вместо ввода ID** — контекстное меню участника (правый клик по нику → **Заявка на
наказание**) сразу открывает выбор типа наказания для уже выбранного участника, без набора
упоминания/ID в анкете вручную. Доступно тем же, кому доступна `/punishment request`. Работает
только для участников, ещё состоящих на сервере (бан/пермбан/кик/предупреждение/снятие
предупреждения).

**Выбор из уже забаненных** — при разбане/снятии пермбана через панель заявок (`/punishment
request`/`/punishment show`) вместо ручного ввода ID открывается список уже забаненных участников
(до 25 сразу, дальше — через `/unban`/`/unpermban` с поиском по вводу). Команды `/unban` и
`/unpermban` для руководства тоже подсказывают ники прямо во время ввода — печатать ID вручную
больше не нужно нигде.

**Уведомления в ЛС** — `/ban`, `/permban`, `/unban`, `/unpermban` (и автоматический разбан по
истечении срока) пытаются написать цели в личные сообщения о наказании/снятии до/после действия;
доставка не гарантирована (например, у разбаненного пользователя чаще всего уже нет общих
серверов с ботом) — статус доставки видно в ответе команды.

**Карточка модерации** — `/modcase` (или контекстное меню участника → **Карточка модерации**)
показывает статус бана (временный/перманентный, причина, кто выдал) и все активные
предупреждения цели одним эфемерным сообщением с кнопками **Разбанить**/снять конкретное
предупреждение — не нужно поднимать историю по разным каналам логов. `/banlist` и `/warnlist`
дают обзор по всему серверу: кто сейчас забанен (с разбивкой на временный/перманентный) и у кого
есть активные предупреждения (по убыванию количества). Все три доступны только
`moderation.leader_role_ids`.

## Объявления и бинды (`/restruct_announce`)

Всё, что публикуется — уходит сразу во все каналы из `restruct_announce.channel_ids`, тегает
выбранные роли и параллельно рассылает то же сообщение в личные сообщения каждому участнику
этих ролей. Доступно только `moderation.leader_role_ids` (own/dep.own).

**Панель** — `/restruct_announce panel` публикует постоянную панель с двумя кнопками (как
`/rules show`/`/cars show`):

- **📢 Создать объявление** — открывает эфемерный редактор (виден только автору): кнопка
  «✏️ Текст» открывает окно ввода заголовка/текста, дальше прямо на этом же экране —
  живой предпросмотр embed'а и кнопки «🎨 Цвет» (полоса embed'а — выбор из готовой палитры
  базовых цветов, без ввода HEX-кода), «🏷️ Теги» (выбор ролей через нативный ролевой
  селектор Discord — кто получит тег и ЛС), «🔘 Кнопки» (кнопки-ссылки под сообщением,
  до 15 штук), «😀 Реакции» (эмодзи, которые бот проставит под опубликованным сообщением).
  «✅ Опубликовать» отправляет во все настроенные каналы + ЛС сразу.
- **🔖 Мои бинды** — личные сохранённые шаблоны рассылки, у каждого в руководстве свой
  набор. «➕ Создать бинд» — тот же редактор, что и для разового объявления, но результат
  сохраняется под именем, а не публикуется сразу; у сохранённого бинда есть «🚀 Отправить»
  (публикация в один клик со всеми настроенными тегами/кнопками/реакциями), «✏️ Редактировать»
  (тот же редактор, предзаполненный) и «🗑️ Удалить» (с подтверждением). Бинды видит и
  использует только тот, кто их создал.

**По команде (без панели)** — `/restruct_announce send` открывает окно ввода заголовка и текста
и сразу публикует (тег — только `restruct_announce.role_id` по умолчанию, без кастомных тегов/
кнопок/реакций — для этого нужна панель). `/restruct_announce edit` редактирует именно последнее
такое разовое объявление, отправленное через `send` (по сохранённым ID сообщений), без повторной
рассылки в ЛС.

## Выдача ролей (`/role`)

`/role member:<участник>` — одна команда, один параметр. В ответ — нативный мульти-select ролей
Discord (тот же компонент, что и в стандартном редакторе ролей участника): текущие роли уже
стоят «фишками», можно убрать любую крестиком и добавить любые другие — со счётчиком участников
и встроенным поиском по названию, ничего печатать в самом боте не нужно.

Как только выбор меняется, бот сразу применяет разницу: чего не было — выдаёт, чего не стало —
снимает. Результат («+ добавлена / − снята», по каждой роли) приходит и автору команды (только
ему), и в лог-канал `roles.log_channel_id` — кто, кому, что изменил и когда. Если какая-то роль
не даётся (бот ниже неё по иерархии), об этом тоже сообщается отдельно, а остальные изменения
всё равно применяются. Доступно только `moderation.leader_role_ids` (own/dep.own).

## Команда /news

`/news [channel] [image]` открывает окно ввода заголовка и текста, затем публикует красивый
embed с баннером в указанный канал (или в `channels.news` по умолчанию). Если картинку не
приложить к команде, используется баннер, заданный через `/img → Баннер новостей`.

## Другие фишки

- **AFK**: при упоминании сотрудника, находящегося в AFK/отпуске, бот подскажет его статус и
  причину; при любой активности в чате статус «AFK» снимается автоматически (отпуск — только вручную).
- **Приветствие новых участников**: помимо embed'а в `channels.welcome`, бот пытается написать
  новичку то же приветствие в личные сообщения (best-effort — если ЛС закрыты, просто пропускает).
  Оба сообщения ссылаются на `channels.recruit_apply` — канал с тикет-панелью заявки в семью.
- **Варны**: каждое активное предупреждение отображается ролью уровня — Warn 1 / Warn 2 / Warn 3
  (роли создаются автоматически при первой необходимости и больше никогда не удаляются ботом —
  переиспользуются для всех участников). При достижении `warns.threshold` (по умолчанию 3)
  активных предупреждений бот пингует роли из `warns.escalation_role_ids` в канале логов **и**
  автоматически банит участника на `warns.auto_ban_days` дней (по умолчанию 3). Каждое отдельное
  предупреждение снимается само через `warns.auto_expire_days` дней после выдачи (по умолчанию
  неделя) — проверка раз в 30 минут.
- **Голосовые каналы**: кроме блокировки/лимита/кика есть кнопка «Передать права» — владелец
  может передать управление личным каналом другому участнику, не выходя из канала.

## Музыка

`/music` публикует плеер с кнопками (добавить трек, пауза, пропуск, стоп, очередь,
перемешать, повтор, громкость, выйти). Достаточно вставить ссылку на YouTube или просто
название трека — искать и играть можно и по ссылке на Spotify (бот найдёт этот же трек на
YouTube, сам Spotify звук по API не отдаёт). Управлять плеером может любой, кто находится
в одном голосовом канале с ботом.

Требования:
- **FFmpeg** должен быть на `PATH`, либо укажите полный путь к `ffmpeg.exe` в
  `music.ffmpeg_path` в `config.json`.
- Для поиска по ссылкам Spotify нужны `music.spotify_client_id` и `music.spotify_client_secret` —
  бесплатно создаются за пару минут на [developer.spotify.com](https://developer.spotify.com/dashboard)
  (Client Credentials, вход пользователя не требуется). Без них ссылки YouTube и обычный
  текстовый поиск работают как обычно.
- `music.idle_disconnect_minutes` — через сколько минут бездействия (пустой канал или пустая
  очередь) бот сам выходит из голосового канала.
- Поддержки VK Музыки нет — ВК закрыл официальный доступ к аудио для сторонних приложений,
  а рабочие обходы нестабильны и могут отвалиться в любой момент.

## Магазин услуг и оплата

`/shop show` публикует каталог услуг с оплатой; `/shop adm` — добавление/изменение/удаление
услуг (цена — только число, в рублях); `/shop payments` — список заказов, ожидающих оплаты,
с возможностью подтвердить вручную. После оплаты бот сам открывает тикет-канал в категории
`tickets.shop.category_id`, доступный только роли `tickets.shop.role_id`.

**Цена «по сложности»** — если в `/shop adm` оставить поле цены пустым, услуга работает иначе:
нажатие кнопки сразу открывает тикет (та же категория/роль, что и у оплаченных заказов), где
покупатель модальным окном описывает задание. В самом тикете кнопок управления нет — как и у
заявок в семью, вся модерация вынесена в отдельный канал.

Модерация таких заказов устроена так же, как список активных заявок в семью (`/moderation`,
см. `cogs/tickets.py`): `/shop moderation`, вызванная в нужном канале, публикует там панель
со списком всех заказов «по сложности» (или используется статический
`shop.quote_moderation_channel_id` из `config.json`, если команду ни разу не вызывали).
Сотрудник выбирает заказ в меню под панелью — открывается видимая только ему рабочая карточка
с полным набором кнопок:

- **Забрать** — заказ обязательно нужно забрать, прежде чем назначать цену (как и с решением
  по заявкам в семью) — так два сотрудника не пересекутся на одном заказе.
- **От администрации** — анонимный ответ прямо в тикет покупателя (та же механика, что и в
  обычных тикетах).
- **Установить цену** — доступна только тому, кто забрал заказ (или руководству). После ввода
  суммы бот генерирует ссылку на оплату тем же провайдером, что и в обычном магазине, и
  публикует её в тикете покупателя с пингом.
- **Закрыть** — с подтверждением, как обычное закрытие тикета: транскрипт уходит в лог-канал
  тикетов, канал удаляется. Если заказ закрыли, не дождавшись оплаты, он просто снимается с
  учёта (уже оплаченные — не трогаются).

Оплата подтверждается тем же фоновым опросом/вебхуком, что и в обычном магазине — новый канал
при этом не создаётся, тикет продолжает использоваться дальше. Список в канале модерации
обновляется сам на каждом шаге: создание заказа, забор в работу, назначение цены, оплата,
закрытие.

Поддержаны два способа приёма оплаты одновременно (можно один, можно оба):

- **ЮKassa** (`yookassa.shop_id` / `yookassa.secret_key`) — полноценный платёжный шлюз:
  создаёт платёж через API, подтверждение приходит почти мгновенно через вебхук. Требует
  регистрации магазина на yookassa.ru (обычно поверх статуса самозанятого).
  Вебхук ЮKassa настраивается на URL Cloudflare Worker'а из [`cloudflare-worker.js`](cloudflare-worker.js) —
  сам воркер пересылает событие в служебный Discord-канал (`yookassa.webhook_relay_channel_id`),
  бот его вычитывает и **сам** перепроверяет статус платежа напрямую в API ЮKassa (телу
  вебхука не доверяем — оно ничем не подписано).
- **ЮMoney-кошелёк** (`yoomoney.wallet` / `yoomoney.token`) — проще в настройке (не нужен
  бизнес-статус), но без вебхуков: бот сам опрашивает историю операций кошелька раз в
  `yoomoney.poll_interval_seconds` секунд (по умолчанию 25).

Если настроена ЮKassa — платежи идут через неё; ЮMoney-опрос при этом остаётся резервной
проверкой на случай, если вебхук не долетел. Если ЮKassa не настроена — всё работает
через один только ЮMoney-опрос.

## Статистика сервера

`/stats show` публикует в текущем канале самообновляющуюся панель — участники (всего,
людей/ботов, онлайн), буст-статус, каналы, роли, инвайты, дата основания, плюс сводка по
самому боту: автопарк, открытые тикеты (отдельно — заявки в семью на рассмотрении),
активные предупреждения, баланс банка, контракты, приватные голосовые каналы, оплаченные
заказы магазина, пункты каталога модов. Обновляется сама раз в `stats.refresh_seconds`
секунд (по умолчанию 300); `/stats refresh` обновляет её немедленно, не дожидаясь таймера.

## Хранение данных

Все данные (автопарк, AFK-статусы, предупреждения, открытые тикеты, приватные голосовые
каналы, отметки на ВЗП) хранятся в JSON-файлах в папке `data/`. Картинки панелей хранятся
как файлы в `data/panel_images/`. Ничего не теряется при перезапуске бота.
